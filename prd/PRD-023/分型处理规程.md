# PRD-023 · 六类资料分型处理规程

> 定案来源：用户 2026-08-08 拍板「**六类资料的处理方式都不一样，不能一概而论**」。
> 本文是 PRD.md §1.3 与北极星「六类资料的关系」的**执行细则**：agent 领任务照本节干活，不套同一模子。
> 每类五栏：①入库通道 ②处理深度 ③资产定位 ④实算与可信口径 ⑤何时做。
> 上位口径不变：状态现算不存两份 / 体检提醒不拦路 / 脏活给 agent / Word 是操作台 PDF 是产物。

---

## 1. 专项（举一反三产）

- **①入库通道**：本地已有产物目录 `举一反三产物/专项卷/<专项名>/`，agent 走**回收任务**（task.类型=回收）。不经收件台上传——源就在本机。
- **②处理深度**：**拆到题级**，每题必填 `stem / answer / 考点 / mother_id / var_level`。`var_level` 取五级递进词表 `认|识|懂|变|再变`；`来源` 记模型卡路径（`解题模型库/<模型>.md`）。题面存在 `gen_*.py` 的 HTML 字符串里（非结构化），必须 agent 读源重抽，不写确定性解析器。
- **③资产定位**：资产 = **母题 + 范式（模型卡 + 算子/系数链）**，题目是范式的实例。丢了题可重出，丢了模型卡这条线就断了 —— 回收时**模型卡与算子标注优先于题面完整度**。
- **④实算与可信**：已有 `解题模型库/_验算/<模型>.py`（采样式恒等校验 + 答案不撞自检）。**已跑过全 PASS 的老专项直接标 `实算=绿`**（拦新不拦旧），新专项无验算件则标 `黄`，不阻断入库。
- **⑤何时做**：**随使用**。M1 只挂 doc 档（26 行已在库）；哪个专项要被检索/复用了才回收它的题。⛔ 不做 22 个专项全量回收。

## 2. 试卷

- **①入库通道**：收件台上传（`.doc` 为主，实测 457 份旧 `.doc` + 少量 `.docx/.pdf`）→ 生成 task.类型=录入。🔴 `.doc` 非 zip 结构，python-docx 读不了，agent 先转 docx 或走 OCR skill。
- **②处理深度**：**拆到题级但不打全 DNA**。必填 `stem / answer / 考点 / 题型 / 来源`（来源 = 卷名+年级+区县/年份）。`steps` 缺失可空——试卷多半只有答案没有过程，别为了补过程去解题。
- **③资产定位**：资产 = **题目本身**（母题池）。一份卷 = 一个 doc + N 个 question，doc 只是来源容器，不是商品。
- **④实算与可信**：**不逐题实算**。原卷带的答案照录，`实算=灰(未验)`。只有当这道题被选进产物（打卡/专项/组卷）时才升级为必算。
- **⑤何时做**：**随使用**。M1/M2 都不批量铺；老师"找不到题"命中缺口时按卷回收。

## 3. 讲义

- **①入库通道**：收件台上传 docx，成对出现（`X（原卷版）.docx` + `X（教师版）.docx`，如 `测试数据/录讲义-科学讲义/`）。🔴 **一课时一对，必须成对登记为同一 doc**——教师版供答案，原卷版供题面。
- **②处理深度**：**双层**。讲义整体挂 doc（`源文件路径` 指原卷版，`备注` 记教师版路径）；其中的**例题/练习拆题入库**，知识点讲解正文**不拆**（那是排版内容不是题）。必填 `stem / answer / 考点 / section`（section = 讲义小节名，保住课时归属）。
- **③资产定位**：资产 = **档案 + 其中的题**双身份。讲义本身是备课要拿的原件（要能整份取回），题是母题池供料。
- **④实算与可信**：答案取教师版原文，`实算=灰`。科学类概念题**不进实算体系**（无可算量），标 `实算=免`。
- **⑤何时做**：**随使用**（备课要哪课时就回收哪课时）。⛔ 不整册铺 —— 单册 236 页级别，全量拆是 M3 之后的事。

## 4. 练习册

- **①入库通道**：收件台上传（Word 或成品 PDF，如 `组书批次9/_成品/五年级科学上册暑假练习册.pdf`）。自产册与外来册**同一通道不同 `来源`**。
- **②处理深度**：**拆到题级 + 保结构**。除 question 必填项外，必须记 `day / section / seq` 三件套 —— 练习册的价值一半在**顺序与分组**，打散了就退化成散题。自产册若有 `_源/` 结构化数据，直搬不重抽。
- **③资产定位**：资产 = **题目 + 编排**（母题池 + 可复用的册结构）。册结构日后是"再出一本同型册"的模板。
- **④实算与可信**：自产册**必绿**（本地已有六查/逐行恒等闸，交付过就是绿）；外来册照录标 `灰`。
- **⑤何时做**：自产册 **M1 直搬**（已结构化的先进库）；外来册**随使用**。

## 5. 课本

- **①入库通道**：收件台上传或本地路径登记，**只建 doc 行 + asset（PDF/图片）**，不生成录入 task。
- **②处理深度**：🔴 **挂档不拆题**。只填 `名称/科目/年级/版本名/源文件路径`。零 question 行。
- **③资产定位**：资产 = **参考档案**。给人翻、给 agent 定位进度用，不是题源。
- **④实算与可信**：不适用，`人工态` 只标 `已归档`。体检不对课本类做"题量>0"检查（否则永远红灯）。
- **⑤何时做**：**M1 建档即可**，此后不再动。将来真要抽题，走 OCR skill 另立 task，不在本类默认流程内。

## 6. 打卡（派生层）

打卡**先分流**，两条路径处理方式完全不同：

### 6A 计算类打卡（确定性通式 → 生成器）

- **①入库通道**：**生成器登记**（人工/agent 一次性登记 `generator` 行）→ 收件台选中生成器 + 配额 + seed → **直出落库**。不走上传，不走 Word。
- **②处理深度**：题级落库，但**每题必须带回溯三件套** `generator_id + seed + params`，`steps` 由生成器直接给（LaTeX 行数组），`考点` 取生成器的 kp 标签。
- **③资产定位**：🔴 **资产 = 生成器（出题算法）；题目只是实例**（用户 2026-08-08 两次拍板）。改题面质量 = 改生成器，不改库里的题。⛔ 老成品（如 200 题旧册）**不转录不入库**。
- **④实算与可信**：**必绿才落库**。绿的定义 = 生成器自带 `verify` 四闸全过（题面独立 sympy 求值 = 声称答案 / 过程逐行恒等 / 题面不撞 / 值域步数）。红题不入库，不是入库后标红。另加**可复现闸**：同 seed 重跑逐字一致。
- **⑤何时做**：**M2 试点一个**（七上有理数混合运算 qbank.py）。⛔ 其他册生成器不铺开，随使用逐个接。

### 6B 非计算类打卡（应用题/图形/规律等，无确定性通式）

- **①入库通道**：agent 出题任务（task.类型=出题），或从已有册 `_源/` JSON 直搬。
- **②处理深度**：题级落库，必填 `mother_id`（指向母题池里的那道题）+ `var_level`（认/识/懂/变/再变）。**无 generator_id**——承认它不可通式复现。
- **③资产定位**：资产 = **母题 + 范式**（同专项），题目是 agent 按范式产的实例，不可机器复现但可人工复刻。
- **④实算与可信**：能算的必算（走 `_验算/逐行恒等校验.py`）；纯文字/图形题走人工目检，`实算=人工绿`。
- **⑤何时做**：M1 直搬已结构化的（三升四 620 题已在库）；其余**随使用**。

## 7. 六类对照总表

| 类型 | 入库通道 | 拆题粒度 | 资产是什么 | 实算口径 | 何时做 |
|---|---|---|---|---|---|
| 专项 | 本地回收任务 | 题级 + 母题/五级 | 母题+范式（模型卡） | 老件直接绿，新件无验算件=黄 | 随使用 |
| 试卷 | 收件台 .doc/.pdf | 题级，不打全 DNA | 题目 | 灰（选用时才算） | 随使用 |
| 讲义 | 收件台 docx 成对 | 档 + 例题/练习；正文不拆 | 档案 + 题（双身份） | 灰 / 概念题=免 | 随使用（按课时） |
| 练习册 | 收件台 Word/PDF | 题级 + day/section/seq | 题目 + 编排 | 自产必绿，外来灰 | 自产 M1 直搬 |
| 课本 | 只建 doc+asset | **不拆题** | 参考档案 | 不适用 | M1 建档，此后不动 |
| 打卡·计算 | 生成器直出 | 题级 + gen/seed/params | **生成器（算法）** | **必绿+可复现，红不入库** | M2 试点一个 |
| 打卡·非计算 | agent 出题/直搬 | 题级 + mother/var_level | 母题+范式 | 能算必算，余人工绿 | M1 直搬已有 |

**三条不能混的红线**：① 课本永不拆题（体检别给它判红）；② 计算类打卡维护算法不维护题（老成品不转录）；③ 试卷/讲义不逐题实算（否则永远做不完）。

## 8. qbank.py 适配契约（M2 落地用）

**源**：`举一反三产物/打卡/七上有理数混合运算打卡/_源/qbank.py`（570 行，实测 2026-08-08）。

**已实测确认**：
- 生成器签名统一 `gen_xxx(rng: random.Random, lv: int) -> Q`，`lv ∈ 1..3`。
- 返回 `Q = {'q': '\(LaTeX\)', 'steps': [str], 'ans': Fraction, 'kp': tuple, 'feat': tuple}`；`build_paper` 另加 `'anchor'`（主锚考点）。
- 🔴 **单题级可复现已验证**：`gen_frac_div(Random(777), 1)` 两次调用题面/过程/答案逐字一致 → **每题一个 seed 即可复现，不必依赖整卷上下文**。
- 整卷 `build_paper(seed, quota, lv, history)` 同 seed 亦逐字一致（20 题实测）。
- 🔴 **可用生成器实际是 13 个不是 11**：`ALL_GENS` 只列 11，`GENS` 注册表另有 `gen_frac_addsub`、`gen_dec_frac_mix`（2026-08-06 补的变体）。**以 `GENS` 为准登记**，`ALL_GENS` 已过期。
- 考点标签 7 个：`sign/order/pow/abs/fracdec/dist/paren`（`KP_CN` 有中文名）。

### 8.1 generator 表登记字段映射

| generator 列 | 取值 | 说明 |
|---|---|---|
| `名称` | `KP_CN` + 函数 docstring 首行 | 如「乘与绝对值除分数（order/abs/fracdec）」 |
| `覆盖考点` | 逗号串，取自实跑一次的 `item['kp']` | 🔴 kp **硬编码在 `Q(...)` 调用里，静态读不到**，必须跑一次取，或登记时人工填 |
| `脚本路径` | `举一反三产物/打卡/七上有理数混合运算打卡/_源/qbank.py` | 相对 ai-bkb 根 |
| `备注` | JSON `{"gen_key":"gen_frac_div","lv":[1,2,3],"sample":"<样例题面>"}` | 见 8.3 缺列说明 |

### 8.2 直出落库字段映射（Q → question）

| question 列 | 来源 |
|---|---|
| `stem` | `item['q']`（保留 `\(...\)` 定界，渲染层吃 MathJax） |
| `answer` | `str(item['ans'])`（Fraction 转字符串，如 `-28`、`-7/3`；**不转 float**） |
| `steps` | `json.dumps(item['steps'], ensure_ascii=False)` |
| `考点` | `','.join(item['kp'])`；主锚另存 `item['anchor']` |
| `难度` | `lv`（1/2/3） |
| `generator_id` | 登记行 id |
| `实算` | `绿`（verify 通过才写行，见下） |
| `hash_L1` | 题面数字归一签名 = `re.sub(r'\d+','N', q)` 的哈希（复用 qbank `_skel` 的同型闸口径） |
| `doc_id` / `day` / `seq` | 由收件台批次指定 |

### 8.3 🔴 现有 schema 缺口（M2 开工前必补，二选一）

1. **`question` 无 `seed` / `params` 列** —— PRD 要求「带 generator_id+seed+params 可复现」落不了地。
   建议加两列 `seed INTEGER`、`params TEXT(JSON)`；不想动结构则把 `{"gen":"gen_frac_div","seed":777,"lv":1}` 塞进 `来源` 列。
2. **`generator` 无 `gen_key`（函数名）列** —— 只有 `名称`，无法定位到具体函数。同上：加列或用 `备注` JSON 兜。

### 8.4 调用契约（建议 sidecar 暴露两个入口）

```
generate_one(gen_key, seed, lv) -> Q      # = GENS 查表拿函数, 传 Random(seed)，单题可复现
verify_one(Q) -> (ok: bool, errs: [str])  # 从现有 verify() 抽出的逐题版
```

🔴 **`verify()` 当前是批量版**：只 return bool、逐题 `print` 带 emoji（GBK 控制台会杀进程），**必须抽出 per-item 版**才能给每行 question 写 `实算` 状态。抽出时保留原四闸不减配。

批次去重交给调用方（不用 `build_paper`）：撞题面/撞骨架（`_skel` 同签名 ≥2）就 `seed+1` 重试，落库只存最终生效的 seed。
